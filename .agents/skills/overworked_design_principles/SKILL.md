# Overworked 设计红线（项目灵魂）

## 功能概述

Overworked 的核心价值不在功能清单，而在**为什么是这样一个东西**。这五条红线是项目的灵魂，**任何功能迭代、代码改动、文案撰写都不可违背**。

这是第一道关。新功能进来、UI 改动、冒泡文案、交互设计——先过这道关，再谈实现。

## 五条不可妥协的红线

### 红线 1：不爹味

**它只反应，不教育。**

绝不主动提醒用户"该休息了""该专注了""你已工作 X 小时"。它只是**瘫在那里**——最高级的提醒是不提醒。

| ❌ 反例（绝对不做） | ✅ 正解 |
|---|---|
| 弹窗"你已经工作 2 小时了，该休息了" | 它自己瘫倒、冒黑眼圈，你自己看了心里有数 |
| 推送通知"今日工作时长超标" | 冒泡"需求好急"，3 秒后消失 |
| 设定目标"今天专注 4 个番茄钟" | 你专注它就庆祝，你摸鱼它就翻白眼，没有目标 |

**判断方法**：把句子主语换成"你"，如果读起来像家长训话——否决。

### 红线 2：数值显示（2026-07-29 调整）

**【调整前】** 不显示 HP/经验条等游戏化数字，状态靠表情和动画传达。
**【调整后】** 显示常驻小细条（体力/心情/存款/时薪）。

调整原因：用户反馈需要直观看到状态变化（验证感知/存档效果）。
仍守的部分：细条用克制的小尺寸（不喧宾夺主），数值仍驱动表情动画（表情是主、细条是辅）。

| ❌ 仍不做 | ✅ 现在的做法 |
|---|---|
| 大型数值面板/设置面板 | 角落小细条 |
| 精确数字弹窗 | 细条 + 表情动画双重传达 |
| 用户可调数值 | 不可调，仅显示 |

**技术含义**：游戏引擎内部有完整数值系统（体力/时薪/心情/存款），但这些数值**绝不通过 Tauri command 暴露给前端**。前端只接收"表情状态"（`Expression::Tired`、`Expression::Excited`），数值在 Rust 侧映射成表情后再传递。参见 `overworked_game_loop`。

### 红线 3：不抢焦点

**永远待在角落，绝不弹窗、绝不遮挡工作区。**

- 默认在屏幕角落，可拖动到任意边缘
- 拖到屏幕中间它会**自己走回角落**（它知道自己的位置）
- 冒泡 3 秒自动消失，不打断你
- 右键菜单只有三项："暂时消失 1 小时""关于""退出"——没有设置面板

**反例**：任何会获取输入焦点、置顶遮挡、或停留需用户操作的 UI 元素，全部否决。

### 红线 4：本地优先

**零账号、零联网、零隐私焦虑。**

- 不注册、不登录、不联网
- 所有数据本地 SQLite，不上云、不同步
- 无遥测、无崩溃上报（或严格 opt-in 且明示）
- AI 文案生成（Phase 3 可选）必须走用户自己的 API key 或本地模型，绝不内置联网调用

**红线延伸（见 `overworked_behavior_sensing`）**：行为感知只记录频率不记录内容、不截屏、不上传。这是这条红线的技术命门。

### 红线 5：反差是灵魂

**可爱像素 × 社畜惨状，这个错位不能丢。**

任何让它"太正经"的设计都要否决。检验方式：

- 加了这个功能，它变得更像一个"正经工具"还是更像一个"惨兮兮的小生物"？
- 它的反应是"正确/有用"优先，还是"好笑/心酸"优先？

| ❌ 反例（破坏反差） | ✅ 正解（守住反差） |
|---|---|
| 加一个"工作时长统计图表" | 它偶尔冒泡"我这个月加了 80 小时班" |
| 加番茄钟倒计时 UI | 专注 25 分钟它"打赢小怪"掉装备 |
| 加成就徽章墙 | "连续 30 天没让它进医院"它对你投来感激的眼神 |

## 功能决策过滤器

任何新功能/事件/交互进来，依次回答：

1. **它会让小生物更像一个"工具"吗？** → 是，否决（违反红线 5）
2. **它会主动提醒/教育用户吗？** → 是，否决（违反红线 1）
3. **它会向 UI 暴露原始数值吗？** → 是，否决（违反红线 2）
4. **它会抢焦点/弹窗/遮挡吗？** → 是，否决（违反红线 3）
5. **它需要联网/账号/上传吗？** → 是，否决（违反红线 4）

**全通过才进入实现阶段**，然后按相关 skill（架构/感知/游戏循环）落地。

## 与其他 skill 的关系

- 这道关过了，**功能层面的设计**交给 `overworked_game_loop`（核心循环、四属性、行为映射）
- 涉及**感知实现**，交给 `overworked_behavior_sensing`（同时它守红线 4 的技术命门）
- 涉及**代码结构**，交给 `overworked_architecture` 和 `overworked_rust_style`

## 检查清单（提交前自检）

- [ ] 这次改动没有让小生物变得"太正经"（红线 5）
- [ ] 没有任何主动提醒/教育用户的文案或弹窗（红线 1）
- [ ] 没有把体力/时薪/心情/存款等数值传到前端（红线 2）
- [ ] 新 UI 元素不抢焦点、不遮挡、冒泡 ≤3 秒（红线 3）
- [ ] 没有引入联网/账号/上传依赖（红线 4）
- [ ] 如涉及行为感知，确认只记频率不记内容、不截屏（红线 4 延伸）
