# Overworked · 桌宠皮肤制作指南

> 给美术看的设计规范。我们定义「要什么」，你定义「长什么样」。

---

## 一、项目简介

**Overworked 是一只住在屏幕角落的小生物。你用电脑，它就在打工。**

它常驻在用户屏幕角落，感知用户的电脑使用行为（打字、挂机、熬夜），用自己的"打工状态"来反映——你加班它受伤，你摸鱼它瘫倒，你卷它就卷。

它是一个**会让人会心一笑的小活物**。用户每天盯着屏幕工作，它在角落陪着你一起熬。

---

## 二、主题与调性

### 一句话调性：**可爱到让人心软，惨到让人心疼**

| 维度 | 说明 |
|---|---|
| **萌** | 角色本身要极度可爱，让人一看就想保护它 |
| **惨** | 它的状态全是社畜的惨状（加班、过劳、被甲方折磨、夜班） |
| **反差** | 最可爱的小生物 × 最惨的打工生活 = 传播力 |
| **不爹味** | 它不教育用户"该休息了"，它只是瘫在那里 |

---

## 三、角色形象

**形象完全由你决定。** 任何风格、任何生物、任何画风都可以。

要求：
1. **一眼就可爱**：用户第一眼看到就想笑/想保护
2. **能传达情绪**：它的脸能表达累/开心/崩溃等状态
3. **能拟人化**：能站立、瘫坐、做"打工"的动作
4. **适合你的画风**：像素风/扁平风/手绘风/3D渲染风都行

---

## 四、技术规格

| 项目 | 要求 |
|---|---|
| **单帧尺寸** | **任意尺寸**（推荐 64×64 或 160×160，系统自动等比缩放显示） |
| **格式** | PNG，**背景必须透明** |
| **色彩** | 不限（像素风建议有限调色板，其他风格自由） |
| **风格** | **不限**——像素风、扁平风、手绘风、3D 风均可 |

### 关键要求
- **背景透明**：不能有任何背景色，否则显示色斑
- **角色居中**：角色在帧内大致居中
- **所有帧同尺寸**：同一套皮肤的所有帧必须尺寸一致
- **walk 只画朝右**：朝左走由系统自动镜像

## 五、39 个动作清单（18 普通 + 21 修仙）

每个动作 = 一个文件夹。文件夹内放序列帧 `1.png 2.png ...`。

修仙模式开启后，这 18 个动作仍用于普通模式（化凡状态）。

| working | 状态·循环 | 2-4 帧 | "它在认真打工" |
| tired | 状态·循环 | 2-3 帧 | "它有点撑不住了" |
| exhausted | 状态·循环 | 2-3 帧 | "它彻底瘫了" |
| overworked | 状态·循环 | 2-3 帧 | "它快不行了" |
| nightshift | 状态·循环 | 2-3 帧 | "它在熬夜，灵魂出窍" |
| happy | 状态·循环 | 2-3 帧 | "它完成了任务，开心！" |
| poke | 交互·按住循环 | 2 帧 | "被戳了一下，吓一跳" |
| drag | 交互·拖动循环 | 2 帧 | "被拽着走，在挣扎" |

| jump | 生动·播2轮 | 2 帧 | "偶尔开心跳一下" |
| leave | 事件·一次性 | 3-4 帧 | "它辞职了，搬着东西走了" |

> 帧数是**建议值**。画 1 帧、3 帧、5 帧都行，系统按实际帧数播放。
> 不画的动作文件夹，系统自动用 idle 替代。

### 修仙模式动作（21 个）

修仙模式下，**每个普通动作都有对应的修仙版**（1:1 映射），穿着道袍 + 修仙特效。
命名规则：`cult_<对应普通动作名>`（如 `cult_idle` 对应 `idle`）。

修仙模式下系统自动用修仙版替换普通版（通过 `resolveAction()` 统一映射），无需手动触发。

#### 道袍配色体系

| 配色 | 用途 | 对应动作 |
|------|------|---------|
| **青色道袍** | 日常修炼 | cult_idle / cult_work / cult_poke / cult_jump / cult_drag / cult_teambuilding / cult_lunchnap |
| **暗青道袍** | 疲惫负面 | cult_tired / cult_exhausted / cult_overworked / cult_nightshift |
| **金色道袍** | 喜庆收获 | cult_happy / cult_return / cult_payday / breakthrough / ascend |
| **紫色道袍** | 出行移动 | cult_walk / cult_vacation / flying |
| **暗色道袍** | 心魔负面 | cult_leave / deviation |

#### 修仙动作总览

| 修仙动作 | 对应普通动作 | 道袍色 | 修仙特效 | 建议帧数 |
|----------|------------|--------|---------|---------|
| cult_idle | idle | 青 | 莲花座 + 灵气光点上浮 | 2-4 |

| cult_happy | happy | 金 | 金光放射 | 2-3 |

| cult_walk | walk | 紫 | 灵气云拖尾 | 3-4 |
| cult_jump | jump | 青 | 凌空气流（下方气流） | 2 |
| cult_leave | leave | 暗 | 雾气弥漫（封山退隐） | 3-4 |

> **fallback 规则**：修仙动作缺失时，自动降级到对应普通动作（如 cult_tired 缺失→用 tired）。所以最简修仙皮肤只需画 cult_idle。

#### 修仙动作设计要点

- **同一个角色换道袍**：修仙动作和普通动作必须是**同一个角色**，只是穿了道袍（不同颜色），不能变成另一个人
- **道袍标志**：宽下摆 + 腰带 + 交领 V 字（让道袍形状可见，区别于西装）
- **盘坐标志**：cult_idle / cult_lunchnap 底部画莲花座或盘腿（打坐姿态）
- **正面 vs 侧面**：cult_walk / cult_vacation 用侧面（和 walk 一致），其他用正面

### 状态动作详细需求（7 个）

#### idle（待机）—— "它就在那儿，活着"
- 触发：用户挂机/空闲
- 情绪：平静、无害、有点无聊
- 帧：站立 → 呼吸下沉 → 眨眼

#### working（干活）—— "它在认真打工"
- 触发：用户在打字
- 情绪：专注、忙碌、有点小压力但还能撑
- 帧：身体轻微上下（打字节奏）

#### tired（累）—— "它有点撑不住了"
- 触发：体力下降
- 情绪：疲惫、委屈
- 帧：头低/前倾，疲惫表情

#### exhausted（瘫倒）—— "它彻底瘫了"
- 触发：体力归零
- 情绪：放弃、躺平
- 帧：完全趴/躺，X 眼或旋圈眼。**这是传播点——"我家桌宠又瘫了"**

#### overworked（崩溃边缘）—— "它快不行了"
- 触发：连续高强度工作
- 情绪：极限、颤抖
- 帧：左右歪斜（颤抖感），黑眼圈

#### nightshift（夜班）—— "它在熬夜"
- 触发：凌晨 1-5 点
- 情绪：困到灵魂出窍
- 帧：打盹姿态，黑眼圈，zZ

#### happy（庆祝）—— "它完成了任务，开心！"
- 触发：连续专注 5 分钟
- 情绪：狂喜、解放
- 帧：蹦跳、抬手庆祝

---

### 交互动作详细需求（2 个）

#### poke（被戳）—— "被戳了一下，吓一跳"
- 触发：用户按住角色
- 帧：惊跳 → 落回

#### drag（被拖动）—— "被拽着走，在挣扎"
- 触发：用户拖动角色
- 帧：身体左歪 → 右歪

---

### 生动动作详细需求（2 个）

#### walk（散步）—— "偶尔散散步"
- ⚠️ **只画朝右方向！朝左系统自动镜像**
- 角色必须是**侧面视角**（脸朝右）
- 帧：迈左脚 → 并拢 → 迈右脚 → 并拢

#### jump（跳）—— "偶尔开心跳一下"
- 帧：跳起 → 落地

---

### 特殊事件动作详细需求（7 个）

> 这些是给日常打工生活加剧情的"惊喜事件"，传播价值最高。

#### leave（离职）—— "它辞职了，搬着东西走了"
- 触发：连续 3 天心情归零
- 帧：抱着纸箱往画面外走

#### return（回归）—— "它回来了，新身份"
- 触发：离职 3 天后
- 帧：背着行李走进画面

#### promoted（升职）—— "它升职了"
- 触发：存款达到阈值
- 帧：自信站姿，头顶多个铭牌/胸章

#### teambuilding（团建）—— "团建！举杯"
- 触发：周五下午 + 挂机
- 帧：举杯庆祝

#### lunchnap（午休）—— "午休，趴着睡"
- 触发：12-13 点挂机
- 帧：趴桌睡，旁边有饭盒

#### payday（发工资）—— "发工资了！在数钱"
- 触发：每月 1 号
- 帧：手里数钱/金币，眼睛放光

#### vacation（度假）—— "它度假去了"
- 触发：存款达到旅游阈值
- 帧：度假造型（墨镜/躺椅/沙滩），持续几天

## 七、文件交付规范

### 命名规则
```
skins/皮肤名/动作名/帧号.png
```
- 文件夹名 = 动作名（小写，必须完全匹配上表）
- 帧文件 = `1.png 2.png 3.png`（从 1 开始连续）

### 示例目录结构
```
skins/
└── 你的皮肤名/
    ├── idle/                    ← 普通模式动作（18 个）
    │   ├── 1.png
    │   ├── 2.png
    │   └── 3.png
    ├── working/
    │   └── ...
    ├── cult_idle/               ← 修仙模式动作（20 个，可选）
    │   ├── 1.png
    │   └── 2.png
    ├── cult_work/
    │   └── ...
    ├── breakthrough/            ← 突破庆祝（修仙）
    ├── flying/                  ← 御剑飞行（修仙，有坐骑时）
    │   └── ...
    └── ...（共 39 个动作文件夹：18 普通 + 21 修仙）
```

### 灵活规则
- **缺动作**：不画的文件夹自动用 idle 替代（修仙动作降级到对应普通动作）
- **帧数自由**：建议帧数只是参考
- **最简皮肤**：只画 idle 一个文件夹就能跑（修仙模式自动复用普通动作）
- **修仙皮肤**：要区分修仙形象，至少画 cult_idle（其他修仙动作会降级到对应普通动作）
- **坐骑/法术**：完全可选，不提供则用程序绘制的默认造型（**推荐不提供**，程序绘制动画更好）

## 八、坐骑造型图（可选，修仙模式专属）

修仙模式下桌宠可以骑坐骑。**默认坐骑是程序绘制的**（带完整动画：剑光拖尾/龙身蜿蜒/凤冠飘动/灵气粒子），你也可以提供美术图替换造型。

### ⚠️ 重要：程序绘制 vs 图片

程序绘制版有**连续动画**（坐骑本身在动），图片版只有静态造型 + 程序叠加的简单浮动效果。
**推荐不提供图片**，让程序绘制版发挥完整动画效果。除非你的美术能做出比程序绘制更好的造型。

### 规范（如果你要提供图片）
- **位置**：`skins/<皮肤名>/mounts/<坐骑名>.png`
- **坐骑名**：`sword`(飞剑) / `gourd`(葫芦) / `dragon`(青龙) / `qilin`(麒麟) / `phoenix`(凤凰)
- **尺寸**：建议 64×32 或更宽（横版，坐骑比角色宽）
- **格式**：PNG 透明背景
- **内容**：只画坐骑本身，**不画角色**（角色由系统叠加在上面）
- **方向**：朝右（与角色一致）
- **注意**：图片是静态的，程序会在上面叠加浮动+发光，但坐骑本身的细节动画（如龙身蜿蜒）会丢失

## 九、法术图标（可选，修仙模式专属）

修仙模式下可以施展法术（全屏特效）。默认法术粒子是**通用发光球/符号**，你也可以提供图标替换。

### 规范
- **位置**：`skins/<皮肤名>/spells/<法术名>.png`
- **法术名**：`fireball`(火球术) / `ice`(冰封术) / `thunder`(雷劫术) / `swords`(万剑诀) / `armageddon`(天地同寿)
- **尺寸**：建议 32×32（小图标，会作为粒子贴图缩放）
- **格式**：PNG 透明背景
- **内容**：法术的标志性图案（火球画火球、冰晶画冰晶、剑画剑形）

### 设计原则
- **运动轨迹由程序控制**：你只画图标"长什么样"，爆裂方向/下劈角度/扩散速度由代码控制
- **有图优先**：提供了图标就用图标做粒子，没提供用通用发光球
- **万剑诀**：图标会作为下落物（原来是 `╫` 符号）

## 十一、测试方法

### 开发版
1. 把皮肤文件夹放进项目的 `skins/`（和 `default` 平级）
2. 启动应用（`npm run tauri dev`）
3. 右键桌宠 →「换皮肤」→ 选你的皮肤名
4. Shift+右键 →「动作预览」逐个检查
5. Shift+右键 →「修仙调试」→「装备坐骑」检查坐骑造型

### 安装版（打包后）
安装版的 `skins/` 在安装目录（通常只读）。自定义皮肤放到：
```
%LOCALAPPDATA%\com.overworked.app\skins\你的皮肤名\
```
（Windows 上按 `Win+R` 输入 `%LOCALAPPDATA%\com.overworked.app` 可快速打开）

### 皮肤持久化
切换皮肤后会自动记住，下次启动恢复上次的皮肤（不用每次重选）。
